# AGENTS.md

## Architecture
- Static site, published from the repo root (`netlify.toml`: `publish = "."`, no build command). The generated HTML is **committed**: run `python3 scripts/build.py` after editing content or templates and commit the output.
- `scripts/pages.json` is the single source of truth for page content. Page fields: `path, category, category_name, card, title, desc, h1, exprs, exam`, plus optional `intro[]`, `points[]`, `examples[{e,l}]`, `faq[{q,a}]`, `fit{data,model}` (preloads the regression panel), `params{}` (default slider values), `updated`, `trend` (adds the page to the home page's "New for 2025–2026" section), and `disclaimer` (overrides `DISCLAIMERS` in build.py).
- `scripts/check_pages.py` checks required fields. `scripts/test-parser.js` runs the parser tests and compiles every page's equations.
- `assets/js/engine.js` (UMD, `window.EGEngine`): `compileExpr`, `createGraph`, `regress(points, model)`, `parseData(text)`, `MODELS`. Compiled kinds: function (no kind), `implicit`, `ineq`, `parametric`, `polar`, `points`.
- `assets/js/app.js`: the UI, driven by `window.EG_CONFIG` (`exprs, exam, category, fit, params`), which build.py injects on each page.
- `sw.js` is generated (its version follows `ASSET_V`). Pages are network-first and `/assets/*` is cache-first.

- Statistics pages (`"stats": "zscore"|"stddev"|"ci"|"ttest"` in pages.json) do not use the graph engine: `page_stats()` renders a form host and `assets/js/stats.js` builds the UI. They take `intro[]`, `sections[{h,p[],ul[]}]` and `faq[]`. Run `node scripts/test-stats.js` after changing the maths.

- **Navigation (v12):** `NAV`/`GUIDES` in build.py define the 6 header categories + guides. Each has a hub page (`exam-prep/`, `functions/`, `trigonometry/`, `calculus/`, `data/`, `statistics/`, `guides/`) generated by `page_hub()`. Each dropdown/drawer group lists only its `top` tools (6) plus "View all". To change popular tools, edit `top` in `NAV`; hub intro/title/desc live there too. The header "More" (3-dot) menu and the mobile drawer are generated by `header()` and `drawer()`; behaviour is in `initCatNav()`/`initDrawerNav()` in app.js.
- The "+" add-item menu (`ADD_ITEMS` in app.js) supports Expression, Note, Table (plots its points), Inference (links to a stats calculator), Folder (groups expressions) and Image (reference preview).

## Conventions
- Bump `ASSET_V` in build.py after any CSS or JS change (assets are served `immutable`).
- Page copy uses US spelling and should be factual. Hedge exam-policy claims ("check the current policy") and give every brand or exam page a trademark disclaimer.
- The graph uses one shared scale for both axes, so keep example and regression data in similar x and y ranges (scale money to thousands, for example).
- Points syntax: `(1, 2), (3, 4)`. Components must not use `t` or `x`, otherwise the text is treated as a parametric curve.
- The email form `cheatsheet` is plain static HTML (Netlify Forms with a honeypot `company` field) and posts to `/thanks/`, which links to `/cheat-sheet/` (both are noindex).

## Site search
- `assets/js/search.js` is hand-written; `assets/js/search-data.js` is generated by `build.py` (`search_index()`) from `pages.json`. Do not edit the data file by hand.
- The animated placeholder phrases live in `SEARCH_HINTS` in `build.py`. Keep them short and make sure each one finds a real page.

## 3D page
- `calculus/3d-graphing-calculator/` is rendered by `assets/js/surface3d.js`. `compileSurface` handles `z = f(x, y)`; if it errors, `compileImplicit3` is tried (equation with z, `F - G = 0`) and `EGMarch.tetra` (in `assets/js/marching.js`) extracts the surface. Add `marching.js` before `surface3d.js` on any page that uses the plotter (build.py `page_surface` does this).
- Very large implicit meshes (> 12,000 triangles) also get a coarse copy (`S.meshLow`) that is drawn while dragging. Presets are `[name, formula, optional box half-size]`.

## Part 2: legal pages, forms, cookie consent
- Legal pages (`about`, `contact`, `privacy-policy`, `terms`) live in `pages.json` > `legal[]` as structured data: `slug, title, h1, desc, updated, intro[], sections[{h, id?, p[], ul[], table{head,rows}, after[]}]`, `contact: true` adds the WhatsApp/email cards and the contact form. `[label](@/path)` in text becomes an internal link. Sections with 8+ headings get a table of contents.
- Contact details are constants at the top of build.py (`CONTACT_EMAIL`, `WHATSAPP`). The cheat-sheet heading/description come from `pages.json` > `signup`.
- Both Netlify forms (`cheatsheet`, `contact`) are static HTML with `data-netlify` and a honeypot. `assets/js/site.js` submits them with fetch to `/` (needs "form-name" in the body), shows inline validation, success and error messages, and falls back to the plain POST (`thanks/`, `thanks/message/`) without JavaScript. In Netlify, Forms must be enabled for the site.
- `site.js` also draws the cookie banner (Accept all / Reject non-essential / Manage). The choice is stored in `localStorage` key `eg-consent` and exposed as `window.EGConsent` (`get()`, `open()`, `onChange(fn)`) and the `data-consent` attribute on `<html>`. Load any future analytics or ad script only after `EGConsent.get().analytics` / `.ads` is true. Footer links with `data-cookie-settings` reopen it. Update the cookie table in the Privacy Policy when storage items change.
- Titles must be <= 60 characters (incl. " | ExamGrapher") and descriptions 120-155; `python3 scripts/seo_check.py --all --meta` enforces this on tool pages and on home, hubs, legal and cheat-sheet pages.

Disabled by default; update the Privacy Policy cookie/analytics text before enabling.

## Calculus syntax (v17)
- `compileCalculus()` in engine.js adds three forms on top of the normal grapher: `d/dx(f)` / `d2/dx2(f)`, `int(f)` / `int(f, a)` / `int(f, a, b)`, and `dy/dx = f(x, y)[, y(x0) = y0]` (slope field plus an RK4 solution curve).
- Derivatives are exact: `diffNode()` differentiates the parsed tree (power, product, quotient, chain, exponential, log, trig, inverse trig, hyperbolic, abs) and `pr()` prints it in the grapher's own syntax. The result is cross-checked against a numerical derivative; if a rule is missing (floor, `?:`, mod...) or the check fails, a five-point numerical derivative is used instead. Both routes return NaN at corners and jumps, and `ext.breakJumps` makes `sample()` leave a gap there.
- `antiNode()` gives antiderivatives only for standard forms (polynomials, sums, constant multiples, powers and standard functions of a linear inner part, c/x^n). It is used for the "F(b) - F(a)" step and is checked against the numerical (Simpson) area. Anything else shows only the numerical value. Trig antiderivatives are not offered in degree mode.
- Results carry `ext` (`area()`, `field()`, `ic()`, `info()`, `breakJumps`), which `app.js` copies onto the equation object. `info()` feeds the sidebar "Formula & steps" panel (`drawSteps()`); the panel and the printed area value are hidden in US Exam Mode. The keyboard has a "calculus" tab. Run `node scripts/test-calculus.js` after changing any of this.

## Part 9: solved examples and sources
- Optional page fields `worked[{title, problem, steps[], answer, graph[]}]` (rendered by `worked()` in build.py as "Solved examples", `graph[]` becomes a "Graph it" link with several `eq=` params) and `sources[[label, url]]` ("Official sources" list, `sources_html()`). All 12 exam-prep pages have both; `worked` is also on the 16 calculus (not 3D), data and compare pages. Every number in `worked` was checked by script; `test-parser.js` also compiles each `graph` expression.
- Exam facts were checked against official sources in Nov 2026 (College Board, ACT, NYSED, Smarter Balanced, GaDOE, VDOE, NCDPI, Desmos state PDFs). Re-check them each school year.

## Part 10: technical SEO
- `head()` (build.py) adds `robots` (max-snippet/max-image-preview), `hreflang` en-us + x-default and `og:locale` on every indexable page; noindex pages get none of these.
- Schema: tool pages emit WebApplication (`@id`, `dateModified`, `featureList`, `audience`, `publisher`), FAQPage and BreadcrumbList; the home page emits an `@graph` with Organization (logo, contact) and WebSite; legal pages emit AboutPage/ContactPage/WebPage + BreadcrumbList.
- `lastmod` is real: `lastmod()` hashes each page's source in `scripts/lastmod.json` and only moves the date when the content changes. Commit `lastmod.json`. Set `BUILD_DATE=YYYY-MM-DD` to override today's date.
- Part 10b: all 28 functions and trigonometry pages have 2 `worked` examples each (math checked by script, every `graph` expr compiled by test-parser); they now run 670-760 words.
- Part 10c: statistics calculators got practice-problem and common-mistake sections (values from SciPy); the 4 graph-based stats pages got `worked` examples; 4 new guides (how to use a graphing calculator, solve equations by graphing, graph a parabola, iPad and tablets) joined `guides/`. 71 tool pages now.
- Part 10d: `page_tool()` now renders optional `sections[]` (same field as stats pages); the 5 guides use it for common mistakes and tips.
- Cheat-sheet flow: the sign-up form asks for name + email, then `site.js` redirects to `/thanks/` (Excel and PDF download links). It fails open: if Netlify Forms is unavailable the visitor still reaches the downloads. `python3 scripts/make_downloads.py` rebuilds `downloads/*.xlsx|pdf` from `pages.json > cheatsheet`.
- `llms.txt` is generated from `pages.json`; `robots.txt` and `sitemap.xml` are as before.
- `python3 scripts/seo_audit.py` is the release gate (exit 1 on failure): one h1, self canonical, title/description length and uniqueness, valid JSON-LD, og/twitter/robots/hreflang tags, image alt, sitemap matches indexable pages, no broken links, at least 3 inbound internal links per page, redirect targets exist. Run it after every build.
